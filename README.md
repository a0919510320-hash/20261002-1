# 採購管理總覽

供主管檢視採購金額、廠商排名、占比，以及後續各期統計變化的網站原始碼。

## 上傳 GitHub

1. 解壓縮本檔案。
2. 建立 **Private（私人）** 儲存庫。此套件含145家廠商名稱及實際採購金額，預覽頁也包含相同資料。
3. 將 `procurement-dashboard` 資料夾裡面的檔案上傳到儲存庫根目錄，讓 `README.md` 與 `package.json` 位於最外層。
4. 請確認隱藏檔 `.gitignore`、`.npmrc` 與 `.openai/hosting.json` 一併保留。若網頁拖放漏掉隱藏檔，可使用 Git 工具提交整個資料夾。

不需將ZIP本身上傳成唯一檔案。這個套件沒有自動發布工作流程；上傳原始碼不會自動啟用線上網站。

## 立即查看

用瀏覽器開啟 `preview/index.html`。這是可離線開啟的單檔預覽，可查看排名、圖表、匯出排名與列印。
預覽不提供匯入及雲端儲存，也不會自動隨原始碼修改而更新。

## 完整網站功能

- 採購總額、廠商數、前十大占比、涵蓋80%採購額的廠商數。
- 全部廠商排名、個別及累計占比、ABC分類。
- 匯入Excel或CSV，檢查欄位、金額與合計後儲存。
- 保留不同統計版本，比較金額差異、占比差異與排名升降。
- 相同統計口徑的歷期金額圖表。
- CSV匯出及報告列印。

初始資料總額為76,335,609，共145家廠商。來源為 `115年廠商年度統計表.xlsx`。
目前介面仍沿用「115年原始統計」標籤，原始表未包含截止日及稅別。
後續補充的1–9月口徑、135,583,039業績與56.3%採購占比，尚未加入此版網站。

## 本機啟動（交給維護人員）

需求：Node.js 22.13.0以上、npm。資料後端使用Cloudflare Workers及D1。

```sh
npm ci
npm run dev
```

開啟終端機顯示的網址。初次啟動尚未建立本機資料表時，原始統計仍可查看，歷期資料會顯示讀取失敗。
要測試保存功能，先完成建置並建立本機資料表：

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_procurement.sql
npm start
```

上述建表指令僅在新的本機資料庫執行一次，不要重複套用。後續修改結構使用 `npm run db:generate` 產生新的遷移檔，保留原有紀錄。

## 部署與存取

GitHub儲存原始碼；GitHub Pages僅能提供靜態頁面，不能執行本專案的 `/api/snapshots` 或D1儲存功能。

原專案採Sites部署流程，`.openai/hosting.json` 已保留 `DB` 邏輯綁定並移除舊站識別碼。交由Sites部署時需註冊新站、套用資料庫遷移，並設定私人存取。

若改為直接部署到Cloudflare或其他平台，需由維護人員設定執行環境、資料庫及存取控制。本專案API依賴私人網站平台的存取保護，沒有獨立登入或角色權限；不得將其直接部署為公開、可匿名寫入的站點。

私人GitHub儲存庫不代表部署後的網站也自動具有私人存取權限。

## 資料更新規則

第一張工作表須包含「廠商簡稱」及「總計金額」欄位。檔案上限5MB、廠商列數上限5,000筆。

- 同名廠商合併加總。
- 名稱恰為「總計」「合計」「小計」的列會略過。
- 金額須為非負數，總額須大於0；含負數調整的表需先確認處理方式。
- 每次儲存新增獨立版本，不覆寫舊版，也不將各份累計表相加。
- 請填寫期間名称、截止日、累計／單期／年度口徑，並維持一致幣別及稅別。
- 比較以廠商簡稱配對，廠商改名需先統一名稱。
- 初始表未提供截止日，因此不納入時間趨勢圖。
